# humanizer-zh-speech

把書面腔／AI 腔的**繁體中文口播稿**，改寫成念出口像真人在講的自然口語——同時清掉中文 AI 寫作痕跡。

> 一句話：**把「寫出來給人讀」的中文，變成「念出來給人聽」的中文。**

這是 [`humanizer-zh`](https://github.com/blader/humanizer) 的姊妹 skill：
- `humanizer-zh` 處理「書面文字像不像 AI 寫的」（給人讀）。
- `humanizer-zh-speech` 處理「這段話念出來像不像真人在講」（給人聽）。

## 為什麼需要它

把文章直接拿去當影片旁白／Podcast 講稿／口播稿念，會「卡卡的、像在讀稿、很假」。因為書面中文和口語中文是兩套語體。本 skill 依**真實語料研究**逐項把書面改成口語。

研究基礎（不是憑感覺）：**435 份台灣 YouTube 口播逐字稿**（6 領域：知識／財經／教學／時事／影視解說／生活）對照 **25 篇正式書面文章**，量化出兩者差距，例如：

| | 口語 | 書面 |
|---|---|---|
| 平均句長 | **9.8 字** | 48.9 字 |
| 句末標點覆蓋率 | 0.5% | 91.2% |
| 語氣詞密度 | **高 36 倍** | — |
| 口語連接詞（所以/然後/其實） | **高 9 倍** | — |
| 人稱代詞密度 | **高 4.3 倍** | — |

完整 12 維分析見 [`references/speech_register_findings.md`](references/speech_register_findings.md)。

## 它會做的事

切短長句（一行一口氣 ≤10 字）→ 換口語連接詞（因此→所以、然而→但是）→ 去名詞化（「進行討論」→「來聊」）→ 省多餘主語 → 拉第二人稱對話 → 按換氣斷行 → 補**功能性**語氣詞（克制，不堆口頭禪）。

**三檔口語強度**可調：穩重（知識/財經旁白）／中性（預設）／閒聊（vlog/談話）。預設偏穩重——因為「先寫稿再念」的講稿型口播，句子短但語氣詞克制，不該被灌成浮誇的即興口吻。

**不會做的事**：不改技術內容、數字、專有名詞、立場；不做事實查核；不是翻譯。對「本來就已經很口語」的稿，改動率應 ≤5%（不為改而改）。

## 安裝

```bash
# 透過 skills CLI（發佈後）
npx skills add kyrie-snow/humanizer-zh-speech

# 或手動：把整個資料夾放到 ~/.claude/skills/
cp -r humanizer-zh-speech ~/.claude/skills/
```

## 用法

在 Claude Code / 支援 skills 的環境裡，直接說：

- 「把這段改成口播稿」
- 「這個旁白唸起來太書面，幫我口語化」
- 「讓這篇像在跟觀眾講話，但不要太浮誇」（→ 穩重檔）
- 「改成很像在閒聊的 vlog 口吻」（→ 閒聊檔）

要貼近你個人口吻：給 3–5 段你自己的口播逐字稿，skill 會萃取你的「聲音指紋」當個人化覆蓋層（見 [`references/example_voice_profile.md`](references/example_voice_profile.md)）。

## 範例

**書面輸入**
> 在當前高度不確定的總體經濟環境之下，投資人之所以普遍感到焦慮，主要是因為利率政策的走向仍不明朗。

**口播輸出（中性檔）**
> 現在這個大環境啊，很不確定。
> 大家為什麼這麼焦慮？
> 說穿了就是利率。
> 到底要往哪走，還看不清楚。

## 設計與限制

- 以**繁體中文／台灣口語**為主。
- 語料偏「講稿型口播」（單人/雙人對鏡頭講述），最貼「把書面稿改成口播稿」的用途；不代表多人自由閒聊或正式演說語體。
- 書面對照樣本量較小（25 篇），倍率為**方向性指標**。
- 完整方法論與誠實邊界見 findings 檔末段。
